Audigy Win16 SoundFont core
===========================

TSF16.H derives the SF2 parser from the Win16 port of
https://github.com/Baron-von-Riedesel/VSBHDA, src/tsf/TSF.H at commit
d14149613d26caa5680d65748c6b8ed0283a6d12 (blob
9b26395cad540a2d212fc88047453cc03057b2fb). The original MIT notice is
in the header. The parser retains PCM16 samples and exports its
sample regions internally to the fixed-point preparation code.

SFLOAD.C owns the bank, allocates shared Win16 blocks, and locks
their complete linear ranges with DPMI 0600h. It releases the same
ranges with 0601h. It reads PCM into 4 MiB blocks and records the
selector for each 64 KiB page in a locked page table.
The loader prepares regions and static filter coefficients using
task-context x87 math. The parser converts Initial Attenuation
using the EMU-compatible 0.04 dB per generator unit.

SFIRQ.C implements the integer playback path. It uses a 24-bit
fractional phase, Q15 gain, Q28 biquad coefficients and 32-bit stereo
accumulators. It uses the driver's existing timestamped event and PCM
queues. The DLL entry has task-only rate, load and release commands.
Command 8 selects 44100 or 48000 Hz before load. The default is 44100.
The loader and integer filter table use the selected rate.
The renderer tracks drum assignment per MIDI channel. It recognizes
GS Use for Rhythm Part and XG/GM2 percussion Bank Select MSB values.
Universal MIDI Master Volume scales the wide mix before clipping.
Task command 9 sets SF2 headroom in dB before opening the SoundFont.
The standalone core starts at 0 dB. The Audigy driver supplies its
configured setting, up to 24 dB. MIDI Master Volume scales that gain. IRQ command 6 stops all voices
and clears sustain while preserving the rest of the MIDI state. Its
high-bit commands cover short/long MIDI, stereo rendering and reset.
Code, static data and the private stack are page-locked before use.
SFTABLE.H is generated by MKTABLES.PY and included for Win16 builds.
SFIRQ uses Watcom medium model for near data and far code. SFLOAD uses
huge model for the sample bank and also uses far code. Both use clibl
for the far-return runtime helpers.
