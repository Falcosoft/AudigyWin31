AUDIGY1 source provenance
========================

Audigy 2.0 includes the confirmed Audigy 1 MIDI and SoundFont changes.
The shared OPL3 and SoundFont source directories are ..\Core and ..\SFCORE.

AUD1POLY lets a new attack replace an old pedal-held voice at
the voice limit when free and releasing slots are exhausted.

AUD1FIX applies generator metadata as byte offsets in the Win16
SoundFont parser, fixing the preset data regression in AUD1TUNE.

AUD1TUNE separates note offsets from scale tuning, corrects the
low-pass damping, and preserves signed SF2 attenuation through
the note gain calculation.

AUD1BAL corrects SF2 Initial Attenuation scaling and the
Channel Volume and Expression curves in SFCORE.

AUD1BIG loads SoundFont samples into resident 4 MiB blocks with
a page table for the integer renderer.

AUD1RST separates midiOutReset from the full synth reset at open.
Both cores implement IRQ command 6 to silence voices while keeping
MIDI settings. A missing SF2 headroom setting defaults to 3 dB.

AUD1VOL3 makes SF2 mix headroom adjustable in MIDI Settings.

AUD1VOL2 extends Universal MIDI Master Volume to OPLCORE.

AUD1VOL passes eight-byte Master Volume messages to SFCORE. The
fixed-point renderer attenuates the wide mix before PCM16 conversion.

AUD1DRUM updates SFCORE.DLL from AUD1MIDI with per-channel percussion
selection for GS, XG and GM2.

AUD1MIDI builds on AUD1SF4. MIDIUI.INC moves MIDI options into a
separate Setup dialog. Both cores accept a task-only rate selection
before initialization. The private PCM geometry and MIDI timeline
follow the selected rate.

AUD1SF3 builds on AUD1SF2 and AUD1MIDQ, with SoundFont loading during DRV_LOAD.
It selects the OPL3 or SoundFont core at startup and reuses the single
existing MIDI port, audio timer and synth stereo pair. SFCORE contains
the SoundFont loader, fixed-point runtime, and Open Watcom build files.

FM mixer / shared reverb test builds on the hardware-tested AUDOPLT1
timer version. It adds an independent FM volume and fader and moves the
shared reverb send before the speaker faders. The private PCM timer and
OPLCORE.DLL are unchanged; there is no new upstream code.

OPL3 MIDI Timer Test 1 builds on AUDOPLR1's private PCM and MIDI queue.
OPLREND.INC replaces the cooperative worker with bounded direct rendering
on the existing Audigy multimedia timer. The supplied OPLCORE.DLL is a
new Open Watcom Win16 build with integer runtime pitch/modulation,
precomputed initialization tables, a saved silent reset image, and a
private interrupt stack. Sources and BUILD.BAT are in ..\Core. The DOSBox
DBOPL engine and Fat Man instruments are retained. See ..\Core\UPSTREAM.TXT
and the separate notices there for their original provenance.

The private PCM path builds on the Audigy 1 Bass Cutoff mixer source.
It reuses the PCM refill engine on a third hardware voice pair. Public
WaveOut count and effect routing are unchanged.

Bass Redirect ports the hardware-tested Audigy 2/ZS filter and mixer
control from AUD2BASM.ZIP to the Audigy 1 v1.5 source. It keeps the original
Audigy 1 board setup; no Audigy 2 CA0151 code or new external code is used.
Analog LFE is DSP output $6B (A_EXTOUT(A_EXTOUT_ALFE) in the existing
VSBHDA/ALSA register references).

Version 1.5 builds on the dual-output software-pause baseline and adds
independent front/rear playback gains. No additional reference code was used.
No new external source was imported. The existing Win16 queue/refill and
hardware voice setup were parameterized. Separate cached volumes now drive
separate DSP gains before common effects. Wave capture taps both raw streams;
speaker-volume changes do not change that recording level. The extended mixer
exposes both playback volumes; existing control identifiers are retained.
ADC formats, physical source routing and effect implementations are unchanged.
Dual-3 fixes duplicate A/B versus muted C/D destinations in output2's routing.
The retained EMU10K1.H reference warns that duplicate send routes are illegal.
Playback volume controls are now enumerated consecutively, preserving IDs.

Version1.4 adds an independently written Win16 mixer facade and optional
application API loader/UI. Its packed interface was checked against the
user-supplied MSMIXMGR.DLL 3.11.0.43 and published Microsoft mixer API
definitions. The Microsoft DLL is NOT included or relicensed. See the
top-level VERIFY.TXT for implementation scope and initial limitations.
The following notices also retain the history of the v1.3 baseline.

Reverb1.3 adds the GPL2-or-later kX Reverb Lite effect by Max Mikhailov
and Eugene Gavrilov. See RVREF.TXT for pinned commit/blob identifiers and
the included original files in REF. Earlier notices and unresolved source
permissions remain applicable; this is not whole-project license clearance.

This extends the user's AUD1IN2 capture backend and accepted AUD1DDL
playback baseline. Earlier author/license notices remain applicable;
this package is not a claim that whole-driver redistribution is cleared.

Configuration/live routing additions
-----------------------------------
Starts from the user-confirmed AUD1WIN version after its Delphi1 CASE fix.
HDA2 DRVPRC.PAS's DRV_QUERYCONFIGURE/DRV_CONFIGURE pattern was inspected
before implementation. The new UI uses the same standard driver hooks but
native resource-free USER controls, rather than adding VCL/DFM initialization
and application-lifetime objects to the audio driver.

AUDCFG.PAS is task-only. Settings are published through short cached-state
requests, applied by the existing resident service, then written to the INI
from normal dialog context. No second multimedia event/private recording API.

Digital capture input constants are verified against the project's pinned
REF/EMU10K1.H and ALSA public definitions:
 A_EXTIN_SPDIF_CD_L/R =02h/03h -> DSP inputs42h/43h
 A_EXTIN_OPT_SPDIF_L/R=04h/05h -> DSP inputs44h/45h
https://git.alsa-project.org/?p=alsa-lib.git;a=blob;f=include/sound/emu10k1.h
https://www.kernel.org/doc/html/latest/sound/cards/audigy-mixer.html
These refer to capture inputs, not playback S/PDIF output routing, and
do not guarantee a connector/accessory is physically present on every card.

Hardware monitoring / native AUX additions
-----------------------------------------
Based on user-confirmed AUD1SET version1; no WOUT mixer changes.
Native AUX structures/functions verified using the supplied MMSYSTEM.DCU,
MMSYSTEM.HLP and local MMDDK.PAS. HDA2 AUXMESSA.PAS supplied the standard
entry-point/message reference, not its unfinished implementation/debug UI.
The working cached WaveOut volume architecture supplies the concurrency pattern.
Independent playback/capture DSP gains follow the existing MACS encoding and
the ALSA Audigy architecture in emufx.c (GPL2-or-later), commit:
906dde0f355bd97c080c215811ae7db1137c4af8
https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/
File: sound/pci/emu10k1/emufx.c at that commit. Existing credits/licenses
above and in CAPREF.TXT/COPYING.TXT remain applicable.
Monitoring adds gain/sample GPRs, not a DMA engine, software resampler or VxD.

AUD1MON2 paired instruction update
---------------------------------
User supplied EK2M v1.01 executable and v1.00 README were inspected as
compatibility references only; no executable code or DSP image was copied.
Executable SHA256:
79fe02dd59f5ec81ab8fb2185c220a426a3dd4661763a843c62c4d5a5a33b8ab
Its input table confirms CD digital42/43 and I2S1 Line-In4A/4B; its output
table confirms analog front68/69 and rear6E/6F. Instruction writer writes
both low and high words. The existing capture path does the same; monitor
source-switch writes now follow that pattern. This is not proof that a
paired-write hardware latch caused the reported silence.
